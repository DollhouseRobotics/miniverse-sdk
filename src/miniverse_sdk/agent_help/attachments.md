# Permanent and closed-loop attachments

Author attachments in the embodiment's MJCF. A primary rigid attachment is a
jointless child body; an additional `<equality><weld .../></equality>` closes
the loop. This is useful for two grippers holding one payload or a parallel
linkage. Do not add attachment metadata to `bundle.json`, new policy joints,
or backend-specific controller code. Welds do not add actuator DOFs.

## Local validation

For an embodiment with equalities targeting Isaac CPU or GPU, install the
optional compiler in the isolated CLI environment:

```bash
uv tool install --force "miniverse-sdk[mjcf]"
miniverse bundle validate robot.mini --json
```

The extra pins MuJoCo to the platform's compiler version. It needs neither
Isaac Sim nor a GPU and does not run a simulation. The ordinary SDK install
remains sufficient for scenes without equalities, including plain MJCF
includes, and for MuJoCo-only bundles. MJCF generators such as `composite`
can create equalities and therefore also require the compiler on Isaac.

Checks apply when either `primarySimulator` or `compatibleSimulators` declares
Isaac. The compiler resolves defaults/classes, includes (regardless of file
extension), body/site references and reference poses. Unsupported equality
types or solver settings, invalid endpoints, and multiple embodiment body
trees fail before upload with a descriptive error and exit status 2. A missing
or mismatched compiler reports `mjcf_validation_dependency` and an installation
command instead of skipping the checks. Upload runs the same preflight.

For portability to the current server asset collector, use `.xml` or `.mjcf`
for included files that themselves reference other includes/assets. The SDK
checks nested nonstandard-extension includes too, but server closure collection
does not yet recurse into those files. Keep this distinction in mind when a
local result succeeds but server import reports unused or missing members.

## Small authoring example

This standalone MJCF is a floating two-arm mechanism with a payload rigidly
owned by the right arm and a secondary attachment to the left arm:

```xml
<mujoco model="closed_loop_payload">
  <option gravity="0 0 0"/>
  <worldbody>
    <body name="base" pos="0 0 2">
      <freejoint name="root"/>
      <geom type="box" size=".1 .1 .1" mass="1"/>
      <body name="left_arm" pos="0 .2 0">
        <joint name="left_hinge" axis="0 0 1"/>
        <geom type="capsule" fromto="0 0 0 .5 0 0" size=".03" mass=".2"/>
        <site name="left_mount" pos=".5 -.2 0"/>
      </body>
      <body name="right_arm" pos="0 -.2 0">
        <joint name="right_hinge" axis="0 0 1"/>
        <geom type="capsule" fromto="0 0 0 .5 0 0" size=".03" mass=".2"/>
        <body name="payload" pos=".5 .2 0">
          <geom type="box" size=".06 .04 .03" mass=".2"/>
          <site name="payload_mount"/>
        </body>
      </body>
    </body>
  </worldbody>
  <equality>
    <weld name="secondary_mount" site1="left_mount" site2="payload_mount"/>
  </equality>
</mujoco>
```

This is an embodiment example, not a complete policy bundle. Add the actuators,
controller and ONNX exports appropriate to your policy using the normal bundle
contract. The guide's XML is compiled by the SDK regression tests.

Body-based welds work too: `<weld name="attachment" body1="left_arm"
body2="payload"/>`. Omitted `relpose` uses the MJCF reference pose, not a later
controller spawn/reset pose. An explicit `relpose` contains position and a
**WXYZ** quaternion; sites supply their own local position and orientation.
Omit `body2` to attach to the world. `active="false"` creates a disabled weld.
Author collision masks and contact exclusions separately; a weld does not
implicitly disable collisions. Start with approximately aligned attachment
frames to avoid large corrective forces.

## Supported scope

- Isaac accepts body/site welds within one embodiment body tree and world
  attachments. Keep a permanently attached payload as a jointless child of
  its primary attachment body, then weld any secondary attachment frames.
- Isaac accepts default `solref="0.02 1"`,
  `solimp="0.9 0.95 0.001 0.5 2"`, and `torquescale="1"`. Tuned soft welds,
  non-weld equalities (including `connect`, joint and tendon equalities), and
  independent free payloads are not supported by this Isaac feature.
- MuJoCo/browser-MuJoCo retain their native equality behavior, subject to the
  platform's existing embodiment support. PhysX fixed joints are not numerically
  equivalent to MuJoCo soft welds, even with default parameters.
- This does not add runtime attach/detach, grasp/release, breaking, toggling,
  or attachments across the embodiment/environment ownership boundary.

The platform derives attachment frames and includes them in `sceneContractHash`.
Existing weld-bearing exports need compatible scene hashes regenerated by the
updated platform exporter and a new bundle revision. This SDK does not generate
or patch those hashes. Non-weld scenes retain their existing scene hashes.
Reset restores the controller/MJCF initial state without rebasing the weld.

This SDK preflight accompanies the platform closed-loop attachment feature
([Miniverse PR #87](https://github.com/DollhouseRobotics/miniverse/pull/87));
installing the SDK alone does not deploy that feature to a server. Server
inspection and backend execution remain authoritative. Validate the exact
uploaded revision with `miniverse test start` on each declared backend,
including motion under load and repeated resets. Local validation or successful
upload is not proof of policy behavior.
